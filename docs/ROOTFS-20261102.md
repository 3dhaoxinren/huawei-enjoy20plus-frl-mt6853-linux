## 安装前必须理解的布局

**rootfs 是文件式根文件系统，不是 userdata 的原始分区镜像；不要执行 `fastboot flash userdata rootfs-v3.ext4`。**

运行布局为：

```text
本机 userdata（F2FS）
└─ frl-linux/
   ├─ rootfs-v3.ext4       # 恰好 4294967296 字节
   └─ v15-deployed.flag    # 本包配套 UUID + 未压缩镜像 SHA256 + staged
```

启动后对应 Linux 路径 `/run/frl/storage/frl-linux/`。不能在旧 rootfs 仍被挂载/使用时覆盖它。
应在已确认挂载关系的恢复环境离线部署，先成套备份旧 rootfs 与旧 flag；不要把别台设备的 userdata 整盘备份写入本机。
两份启动附件应按已有 FRL 启动分区流程选择，不能只看文件名把它们写到任意分区。
本发布不声称提供通用一键刷机器。

目标手机须保留自己的兼容原厂 `super`：代码核对大小 `4798283776` 字节，
前 `1048576` 字节 SHA256 为 `b63efda689240780b9990c573f2a3c9b91e0f737eac5f6269aa2be5aa0432b6f`。
不匹配的固件布局会明确拒绝，不能删除校验强行通过。
禁止用别机 NVRAM/NVDATA/OEMINFO/PERSIST 替换本机身份与校准数据。

## 离线校验与首次使用

解压发布 ZIP，在电脑运行 `python tools/verify_candidate.py`。成功返回 `passed: true` 后，
再按本机恢复环境的部署流程准备 rootfs 和 flag。压缩包的 SHA256 另见 Release 附件。

首次进入本地界面后重新配网。SSH 用户为 `frl`，只接受公钥；应从本机终端把自己的公钥加入
`/etc/frl/ssh/authorized_keys/frl`，核对新主机指纹再连接。不要发送或公开自己的私钥。

如需回退，在恢复环境恢复成套旧 rootfs + 旧 flag；若改了启动分区，则同时恢复本机对应的原始启动分区备份。
不要在线覆盖正在运行的根镜像，不要把失败状态简单改为 accepted 来绕过校验。
