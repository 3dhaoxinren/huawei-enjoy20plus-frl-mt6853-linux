# 导出工具设计

## 目标与边界

把可用 FRL 原生系统转成私有的重建输入材料，解决另一台电脑获取当前版本的问题。不是完整发行包生成器，也不自动证明净化完成或可刷机。

## 实现

Python 标准库管理 OpenSSH 子进程；手机以现有免密码 sudo 运行只读 Python 检查与 GNU tar。归档二进制直接写电脑文件句柄，不经 PowerShell 文本重定向。Tkinter 界面通过线程与队列等待 SSH，不在 UI 线程进行传输。

1. 检查 SSH 主机密钥与公钥认证、原生 `frl-init` / ARM64 / MT6853 身份。
2. 校验当前完整 payload，记录软件包状态、内核、挂载与布局。
3. 白名单顶层目录 + 排除模式 + `--one-file-system` 导出，不复制原始分区。
4. 导出后重新核对 payload 和 dpkg 状态；有任何不一致或非零退出就不成功。
5. 电脑完整读取 gzip/tar，检查排除项、路径、类型、CRC、硬链接及各个 payload 文件 SHA256；再发布本地完成标记。

工具不自动解包归档，因此 Linux 文件系统里的绝对符号链接不会在电脑上被跟随写入。未来重建必须在隔离的 Linux 目录/文件系统中进行。

## 权衡

- 复用 SSH/GNU tar，不实现自有传输协议、文件系统解析或设备刷写。
- 不冻结生产系统、不停止服务；以配置/包状态前后核对发现常见竞态，但不冒充冷备。
- 排除常见敏感位置，仍把所有结果标为 private；自定义 `/etc`、`/opt`、`/var/lib` 内容需要人工/规则审查。
- 严格主机验证和 BatchMode 可避免密码弹窗或错误主机的静默导出，但要求用户先建立可信 SSH 登录。
- 子挂载不会自动打包；若受跟踪文件只存在于未导出的挂载中，电脑校验会拒绝完成，而不是悄悄交付缺失文件。

## 测试与待验证

`test_collect.py` 覆盖命令参数、排除策略、归档 CRC/路径、payload、usrmerge、硬链接、失败回执和本地模拟 SSH 流程。GUI 可做无连接控件测试。真实手机传输尚未测试，不把本地模拟成功算作设备验证。

## 首次审查记录

- Windows 单元测试通过 17 项，Linux 专用 GNU tar 测试跳过；WSL Linux 全部 18 项通过。
- Windows Tkinter 窗口与控件初始化、默认值和初始禁用状态检查通过；未连接手机。
- 在 x86 Linux 主机执行真实远端检查脚本，正确拒绝非 ARM64 设备且未输出归档。
- 模块完整性检查通过。质量检查提示归档校验/传输事务的复杂度，以及较长 UI 布局行；暂保留单文件可直接分发结构，关键拒绝路径有回归测试。
- 模式安全扫描器将 `subprocess.Popen(command, ...)` 标为“路径遍历”。人工复核为误报：此处是参数数组启动 OpenSSH，不是归档解包或拼接目标文件路径；无 `shell=True`，主机/用户/端口受限，私钥路径是用户明确选择的单独参数，输出使用新建独立目录。本工具从不解包收到的归档，且归档路径穿越有拒绝测试。扫描器原始结果保留在私有构建记录，不冒充“扫描器无发现”。
